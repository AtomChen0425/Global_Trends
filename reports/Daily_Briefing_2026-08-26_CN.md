**背景**

文章提出了一种名为 "SELF" 的新可执行文件格式，其核心理念是将程序本身作为一个 SQLite 数据库来处理。这种方法旨在简化软件分发和状态管理，将程序代码、配置、网站内容乃至运行时状态全部整合到一个单一的数据库文件中。这与传统的将程序、数据和配置分散存储在文件系统不同，极大地减少了对 `/var/`、`/tmp/` 或 `/home/` 等目录的依赖。

**技术实现**

SELF 格式利用 `binfmt_misc` 机制，允许自定义解释器来处理可执行文件。当系统尝试执行 SELF 文件时，`binfmt_misc` 会拦截该请求，并启动一个预设的解释器。这个解释器负责解析 SQLite 数据库中的特定表（如 `segments` 表），将程序的不同段映射到内存，并跳转到程序的入口点执行。关键在于，程序在运行时可以通过 `argv[0]` 获取到自身的文件路径，并独立地打开并查询这个 SQLite 数据库，实现对自身数据的读写操作。这种机制使得程序能够以事务性的方式在同一个文件中存储和更新其运行时状态。

**应用场景**

文章以 `self-httpd` 作为一个概念验证（Proof-of-Concept）进行了展示。`self-httpd` 是一个单文件 Web 服务器，它本身就是一个 SQLite 数据库。该数据库不仅包含了 Web 服务器的程序代码，还存储了网站的 HTML 内容、路由配置以及所有访问者的日志和交互数据（如按钮点击记录）。这意味着，Web 服务器的所有信息都整合在一个文件中，并且所有状态的更新都直接写入到程序自身所在的数据库中。这种高度集成的特性为构建轻量级、易于分发和管理的应用程序提供了新的思路，尤其适用于嵌入式系统、微服务或需要快速部署的场景。

**总结**

SELF 格式将可执行文件转变为一个可查询的数据库，实现了程序代码与运行时状态的深度融合。通过 `binfmt_misc` 和 SQLite 的结合，它极大地简化了文件系统的依赖，并允许程序在同一个文件中进行事务性的状态管理。这种“可查询的可执行文件”（Actually Queryable Executable）的概念，借鉴了类似 redbean 的单文件可执行文件的思想，但通过 SQL 接口提供了更强大的数据操作能力，为构建高度集成和易于管理的应用程序开辟了新的可能性。

**技术实现：**

**应用场景与总结：**

LeFlow在四个主要的面向目标的像素控制基准测试中取得了显著成效。通过用摊销的潜在规划和固定预算的回滚选择取代迭代的动作空间优化，LeFlow在成功率上实现了持续提升，同时将规划时间缩短了一个数量级。这一成果表明，潜在世界模型不仅应支持预测能力，还应能够提供可复用的规划先验，从而极大地提升了规划的效率和智能性。
